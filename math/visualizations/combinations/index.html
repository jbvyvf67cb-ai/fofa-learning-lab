Combinations — when order doesn't matter

Sometimes you don't care about the order — only how many. Counting those turns into a beautiful triangle.

In Lesson 3 order mattered — (1,5) and (5,1) were different. But often we only care how many, not the order. Flip 4 coins: if all I ask is "how many Heads?", then HHTT and HTHT are the same answer to me. Counting those groups is called a combination.

1 Group the flips by how many Heads

The bin sizes for 4 coins are 1, 4, 6, 4, 1. Those counts — the number of ways to get 0, 1, 2, 3, 4 Heads — are the combinations. We write "the number of ways to get k Heads in n flips" as C(n, k), read "n choose k".

2 Stack the counts → Pascal's triangle

Write each row's counts under the last and something magic appears: every number is the sum of the two just above it. This is Pascal's triangle, and row n is exactly the combinations for n flips.

Click any number to see what it counts — and the two numbers above that add up to it.

Why does adding work? To get k Heads in n flips, look at the last flip: either it's Heads (then you needed k−1 Heads in the first n−1 flips) or Tails (k Heads in the first n−1). Add those two cases → C(n,k) = C(n−1,k−1) + C(n−1,k). That's the two-above rule.

3 "Choose" = pick which ones

Another way to see C(n, k): it's the number of ways to choose which k of the n flips are the Heads. Pick k below and see all the ways to place them.

Choose k = Heads among 4 flips
Each row is one way to choose which flips are Heads. Count the rows — that's C(4, k), the same number as the bin and the triangle.
